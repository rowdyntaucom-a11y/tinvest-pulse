## Purpose
Continue the approved Snowball-depth roadmap by turning the already reviewed deterministic `goalProjection` calculation boundary into a visible, flexible Goal workspace without changing financial formulas or inventing future-return assumptions.

- current `main` and recent commits;
- `QVANIX_RESPONSIVE_REQUIREMENTS.md`;

- existing `goalProjection.ts` and app/personalization shell.

## Implemented
- Added a new top-level `ЦЕЛЬ` workspace and registered it as an optional startup workspace.
- Current capital is read from the real portfolio snapshot and is not user-reinvented inside the scenario.
- Future assumptions remain explicit user inputs: target in today's RUB, horizon, monthly contribution, contribution indexation, inflation, price return, payout yield and optional benchmark/index return.
- Reinvestment is a visible explicit toggle.
- Required future fields start empty. No default expected return, inflation or benchmark return is generated by QVANIX.
- Incomplete scenarios show an intentional empty state; invalid inputs fail closed through the existing calculation boundary.
- Result presentation separates ending nominal capital, real/today-RUB capital, inflation-adjusted target, progress, own contributions, non-reinvested payouts, optional benchmark capital and scenario-only target crossing.
- Added an interactive yearly trajectory chart for capital vs inflation-adjusted target and optional benchmark scenario.
- Added explicit `СЦЕНАРИЙ, НЕ ПРОГНОЗ` and no-promised-date language.

## Methodology integrity
`v2/src/features/goals/goalProjection.ts` was not modified in this pass. The visible workspace reuses the existing versioned deterministic boundary as-is.

Price return and payout yield stay separate, so reinvestment does not silently double-count a total-return assumption. Benchmark return remains optional and user-authored; QVANIX does not invent expected index performance.

No TWR, XIRR, IMOEX, Risk, Income, Bond, broker/API, credential, trading or DNA calculation semantics changed.

## Responsive / interaction review
- Desktop uses a two-column parameters/results composition.
- Tablet/smaller windows reflow to one column.
- Narrow phones collapse input and result grids without page-level horizontal scrolling.
- The year selector uses deliberate local horizontal scrolling instead of shrinking labels below readability floors.
- Touch/keyboard controls use native inputs/buttons and visible focus states.
- No fixed viewport-dependent content height was introduced.
