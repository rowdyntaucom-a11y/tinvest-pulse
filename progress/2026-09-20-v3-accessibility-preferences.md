# QVANIX v3 — Accessibility interaction preferences

Date: 2026-09-20

## Why
The mobile readability floor is now in place, but a premium mobile product also needs predictable keyboard/switch focus, touch-safe primary controls and respect for OS accessibility preferences. This is a UX/comprehension hardening pass only; it does not alter financial methodology, trust boundaries, demo isolation or data contracts.

## Implemented
- Added a coherent `:focus-visible` treatment for interactive controls using the active shell accent and card surface.
- Locked primary navigation/state controls to a 44px minimum touch height without inflating decorative chips.
- Added `prefers-reduced-motion: reduce` handling that suppresses atmosphere/interaction motion while preserving state changes and financial meaning.
- Added `prefers-contrast: more` shell-aware boundary and muted-text strengthening for Core, Horizon and Carbon.
- Kept Pulse screenshot behavior and financial calculations untouched.
- Extended the already-registered mobile readability regression so the accessibility contract runs in the canonical v3 test suite.

## Product rule
Accessibility preferences adapt presentation, never financial values, trust state, source identity or methodology.
